# 第 3 章：实现你的第一个标签

> 状态：草稿（AI 起草）
> 责任人：@olinex
> 依据：`internal/tagengine/engine.go`、`internal/manager/views/tag/tag_rule.go`

本章把第 2 章的规则真正保存到平台，并用试运行确认它会命中。

## 你将完成什么

- 在「标签事件 → 标签规则」中创建一条启用状态的规则。
- 用编辑器校验和试运行确认规则命中预期流量。
- 在流量详情中核对打标结果。

## 前置条件

- 已完成[第 1 章](01-ingest-traffic.md)，平台中有可用的 HTTP 流量记录。
- 已读[第 2 章](02-rego-basics.md)，理解 `package zki`、`tags` 与输入字段。
- 当前账号在目标命名空间有标签规则的写权限。

## 步骤

### 1. 打开标签规则页

进入「标签事件 → 标签规则」，点击新建。

验证：新建对话框包含名称、目标模型、描述、启用与 Rego 编辑器。

### 2. 填写基础信息

| 字段 | 示例 |
| --- | --- |
| 名称 | `login-post` |
| 目标模型 | HTTP 流量模型（网络层 HTTP 传输） |
| 描述 | 为 POST 到 /login 的请求打标签 |
| 启用 | 开启 |

同一命名空间与模型下，名称不能重复。

验证：名称为空或重复时，保存按钮不可用或提示冲突。

### 3. 写入规则

在 Rego 编辑器中粘贴：

```
package zki

import rego.v1

tags contains "http-login" if {
	input.method == "POST"
	contains(input.url, "/login")
}
```

验证：点击「校验」，编辑器下方不再出现语法、包名或 `tags` 相关错误。编辑器旁的「生成骨架」可插入一份符合契约的最小模板，适合从零开始。

### 4. 用试运行确认命中

点击「试运行」，在样例输入中选择：

- `http-example`：平台预置的真实 HTTP 样例。
- 或手动编辑一段 JSON，确保 `method` 为 `POST`、`url` 包含 `/login`。

验证：

- 「标签结果」中出现 `http-login`。
- 「规则明细」显示该规则的命中情况。
- 把 `method` 改成 `GET` 后重跑，标签不再出现，说明规则只命中预期场景。

### 5. 保存并启用

点击保存。回到列表后确认：

- 规则状态为启用。
- 版本号为初始版本。
- 修改规则会生成新版本，可在版本记录中查看。

验证：列表中出现 `login-post`，且启用开关为开启。

### 6. 在流量详情中核对

打开「流量审计 → HTTP 传输」，找到一条 `POST /login` 的记录，查看详情中的标签区域。

验证：该记录带有 `http-login` 标签；不满足条件的记录没有该标签。

> 新产生的流量会由 worker 按最新规则打标；刚保存规则时，已入库的历史记录不会自动回填标签，请以新流量或试运行结果为准。

## 成功标志

规则列表中存在启用的 `login-post`，试运行命中预期标签，且新流量的详情中能看到 `http-login`。

## 常见问题

- **试运行没有标签**：确认样例 JSON 满足规则条件；确认选择的模型与规则一致。
- **保存被拒绝**：多为组级编译冲突，检查同组规则是否同时整体赋值 `tags` 又使用 `tags contains`。
- **新流量没有标签**：确认规则处于启用状态、命名空间正确、worker 正常消费任务。
