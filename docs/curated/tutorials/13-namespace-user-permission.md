# 第 13 章：命名空间、用户、权限与用户组

> 状态：草稿（AI 起草）
> 责任人：@olinex
> 依据：`internal/models/core/rbac_policy.go`、`internal/manager/views/admin/admin_group.go`、`internal/models/core/namespace.go`

本章完成团队协作的最小闭环：建命名空间、建用户、用用户组与策略授权，并验证租户隔离。

## 你将完成什么

- 创建一个命名空间，并理解系统命名空间的只读边界。
- 创建用户与用户组，为组配置策略，把用户加入组。
- 用新账号验证：只能看到被授权的命名空间与资源。

## 前置条件

- 拥有「系统管理 → 用户 / 用户组 / 命名空间」的管理员权限。
- 已确定团队的角色划分与资源范围。

## 步骤

### 1. 理解四个概念

| 概念 | 作用 |
| --- | --- |
| 命名空间 | 租户边界；规则、数据源、通知、AI 文档与记忆、报告都按命名空间隔离 |
| 用户 | 登录账号，可加入多个用户组，并按组+命名空间获得权限 |
| 用户组 | 权限载体，承载一组策略 |
| 策略 | `目标 + 动作 + 影响`，在某个命名空间内生效；影响为允许或拒绝 |

系统命名空间存放代码声明的公共知识，对所有租户只读，禁止删除。

验证：命名空间列表中看不到系统命名空间；相关资源在系统命名空间下不可编辑。

### 2. 创建命名空间

进入「系统管理 → 命名空间」，点击新建：

| 字段 | 说明 |
| --- | --- |
| 名称 | 唯一，创建后不可修改 |
| 描述 | 说明该命名空间的用途 |

验证：列表出现新命名空间；重复名称会被拒绝；创建后名称字段不可编辑。

### 3. 创建用户

进入「系统管理 → 用户」，点击新建：

| 字段 | 说明 |
| --- | --- |
| 用户名 | 登录名，创建后不可修改 |
| 密码 / 确认密码 | 初始密码 |
| 昵称 | 展示名 |
| 邮箱 | 联系方式 |

创建后用户默认可用；可在用户详情中停用、重置密码或调整用户组。

验证：用户列表出现该账号且状态可用；用该账号能登录，但暂时看不到业务资源。

### 4. 创建用户组并配置策略

进入「系统管理 → 用户组」，点击新建：

- 填写名称与描述。
- 在策略编辑区添加策略行：从平台提供的目标与动作列表中选择，再选择影响（允许/拒绝）。
- 需要限定命名空间时，在策略中指定命名空间。

建议按角色建组，例如「安全运营」「只读审计」「平台管理员」，避免给个人单独配策略。

验证：组详情中的策略行显示动作、目标与影响；目标与动作必须来自列表，不能手填。

### 5. 把用户加入组

回到「系统管理 → 用户」，编辑目标用户，在用户组区域添加组，并选择该关系生效的命名空间。

验证：用户详情中的用户组列表显示组名与命名空间。

### 6. 验证隔离与授权

用新账号重新登录，或在新无痕窗口登录：

- 命名空间切换器中只出现被授权的命名空间。
- 只能看到被授权范围内的规则、数据源、通知、报告等资源。
- 尝试访问未授权资源应被拒绝。

验证：

- 未授权命名空间不可见或不可选。
- 越权接口返回 401/403。
- 在被授权命名空间中可正常读取或写入（取决于策略中的动作）。

### 7. 管理访问密钥

访问密钥属于个人账号：进入「个人资料 → 访问密钥」创建、启停与设置过期时间。

AI 周期性报告在运行期使用计划属主的访问密钥调用只读接口，因此计划属主必须至少有一个启用且未过期的密钥。

验证：密钥创建后可立即用于 CLI 或报告运行；停用后相关调用失败。

## 成功标志

新用户登录后只看到被授权的命名空间与资源，越权访问被拒绝，且周期性报告能使用属主密钥正常执行。

## 常见问题

- **用户登录后什么都看不到**：用户未加入任何组，或组的策略未覆盖目标命名空间。
- **命名空间不可改**：名称创建后不可修改；需要改名请新建并迁移资源。
- **系统命名空间不可编辑**：这是设计约束，系统知识由代码声明，只读共享。
- **报告运行提示未授权**：计划属主缺少启用且未过期的访问密钥，或密钥所属账号失去对应权限。
- **AI 工具越权**：AI 工具调用同样经过权限边界，不会绕过用户组策略。
