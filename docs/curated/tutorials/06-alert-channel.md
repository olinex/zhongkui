# 第 6 章：接入告警渠道

> 状态：草稿（AI 起草）
> 责任人：@olinex
> 依据：`internal/pkg/message/email.go`、`internal/pkg/message/webhook.go`、`internal/models/core/notification.go`

本章把平台内已经产生的告警投递到邮件或 Webhook，并在发送记录里确认结果。

## 你将完成什么

- 创建邮件或 Webhook 通知渠道。
- 创建通知目标，并组织到通知组。
- 把标签事件规则绑定到通知组或目标，收到第一条外部告警。

## 前置条件

- 已完成[第 5 章](05-first-risk-rule.md)，能产生 `alerting` 事件。
- 具备 SMTP 账号或一个可接收 POST 的 Webhook 地址。
- 当前命名空间有通知管理的写权限。

## 步骤

### 1. 创建通知渠道

进入「通知管理 → 通知渠道」，点击新建：

| 字段 | 说明 |
| --- | --- |
| 名称 | 渠道名称，例如 `ops-email` |
| 类型 | `email` 或 `webhook` |
| 启用 | 开启 |
| 配置 | 按类型填写，见下 |
| 描述 | 可选 |

邮件渠道配置：

| 字段 | 说明 |
| --- | --- |
| 主机 | SMTP 服务器地址 |
| 端口 | 默认 25；465 使用隐式 TLS，587/25 使用 STARTTLS |
| 用户名 / 密码 | SMTP 认证信息，密码加密存储 |
| 发件人 | 发件邮箱地址 |

Webhook 渠道本身没有必填配置，接收地址放在目标里。

验证：保存后渠道列表中类型、启用状态正确；配置列显示为加密值。

### 2. 创建通知目标

进入「通知管理 → 通知目标」，点击新建：

| 字段 | 说明 |
| --- | --- |
| 名称 | 目标名称，例如 `oncall-mail` |
| 渠道 | 选择第 1 步的渠道 |
| 语言 | 决定模板语言，例如简体中文 |
| 启用 | 开启 |
| 配置 | 邮件填收件地址 `to`；Webhook 填 `url` 与可选 `headers` |

Webhook 地址必须是绝对 `http://` 或 `https://` 地址；平台以 JSON POST 投递，`2xx` 视为成功。

验证：目标列表中「所属渠道」「渠道类型」「渠道状态」与第 1 步一致。

### 3. 组织通知组

进入「通知管理 → 通知组」。

- 每个命名空间至多一个默认通知组（由数据库唯一约束保证）；未在规则上指定通知方式时使用它。
- 可以新建通知组，把多个目标绑定到同一组，实现一次告警多渠道触达。

验证：默认组标记为「默认组」；自建组的目标数与你绑定的目标数量一致。

### 4. 绑定到标签事件规则

回到「标签事件 → 标签事件规则」，编辑第 5 章的规则，在「通知方式」中选择：

- 使用命名空间默认通知组。
- 指定通知组。
- 直接指定通知目标。

通知目标优先级高于通知组，二者互斥；都不选时回落到命名空间默认组。

验证：保存后规则详情中的通知方式与选择一致。

### 5. 使用通知模板

「通知管理 → 通知模板」中可以查看已注册的事件模板。未在命名空间中维护自定义模板时，平台回退到内置的中英文默认模板（标题与正文分别来自 `notify.{template}.title` / `notify.{template}.content` 翻译键）。模板渲染失败会中止发送，不会以空内容投递。

验证：模板列表能看到标签事件告警对应的模板；删除自定义模板后会回落到默认模板。

### 6. 确认实际发送

触发一次新的 `alerting` 事件，或等待下一次检测。

验证：

- 「通知管理 → 发送记录」出现该事件的发送记录，状态为成功。
- 邮箱或 Webhook 接收端实际收到消息。
- 标签事件记录详情的「关联发送记录」区域能看到目标、渠道、状态与消息 ID。

## 成功标志

一次新的 `alerting` 事件在发送记录中为成功，且外部接收端收到内容正确的告警。

## 常见问题

- **发送失败**：检查 SMTP 主机/端口/TLS 模式、认证信息、发件人是否被允许；Webhook 检查地址可达、返回码为 `2xx`。
- **渠道或目标被停用**：停用后不会发送，确认启用状态。
- **收不到但发送记录成功**：检查垃圾邮件目录、Webhook 接收端日志与 headers 校验。
- **告警被 suppressed**：抑制窗口内不会重复发送，调整规则或等待窗口结束。
