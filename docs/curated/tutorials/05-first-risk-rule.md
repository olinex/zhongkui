# 第 5 章：实现你的第一个风险规则

> 状态：草稿（AI 起草）
> 责任人：@olinex
> 依据：`internal/manager/views/tag/tag_event_rule.go`、`web/src/pages/[language]/tag-event/tag-event-rule.vue`

本章把第 3 章的标签变成条件，配置窗口与阈值，最终在「标签事件记录」中看到第一条 `alerting` 告警。

## 你将完成什么

- 创建一条启用状态的标签事件规则。
- 用条件表达式引用第 3 章的标签，并设置窗口、阈值与抑制窗口。
- 通过试运行与真实检测，看到状态为 `alerting` 的事件记录。

## 前置条件

- 已完成[第 3 章](03-first-tag.md)，`http-login` 标签能稳定命中。
- 已读[第 4 章](04-tag-event-lifecycle.md)，理解条件、阈值与状态流转。
- 当前命名空间有标签事件规则的写权限。

## 步骤

### 1. 打开标签事件规则页

进入「标签事件 → 标签事件规则」，点击新建。

验证：新建对话框包含名称、描述、通知方式、抑制窗口、全部条件满足、启用与条件集合。

### 2. 填写规则基本信息

| 字段 | 示例 |
| --- | --- |
| 名称 | `login-burst` |
| 描述 | 5 分钟内登录请求超过阈值 |
| 通知方式 | 先保持「使用命名空间默认通知组」 |
| 抑制窗口（分钟） | `60` |
| 全部条件满足 | 关闭 |
| 启用 | 开启 |

验证：名称为空时保存按钮不可用。

### 3. 配置第一条条件

在「条件集合」中新增条件：

| 字段 | 示例 |
| --- | --- |
| 条件名称 | `login-tag-hit` |
| 目标模型 | 留空（不限制） |
| 标签维度 / 维度值 | 留空（不限制） |
| 时间窗口（分钟） | `5` |
| 阈值 | `10` |
| 标签表达式 | `http-login` |
| 启用 | 开启 |

含义：最近 5 分钟内，命中 `http-login` 的标签次数超过 10 次即触发。

验证：点击条件上的「校验」，表达式通过；把表达式改成 `http-login AND` 应出现错误并带条件序号。

### 4. 用试运行确认判定

点击「试运行」。试运行使用候选规则即时检测、不落库，且只检测启用状态的条件。

验证：

- 「检测事件」区域出现该条件对应的命中结果。
- 「命中 N 个条件」与实际配置一致。
- 调整阈值或窗口后重跑，结果随之变化。

### 5. 保存并等待检测

保存规则并保持启用。

检测由 worker 的游标调度器推进，平台会按检测时刻统计最近窗口内的标签。流量持续产生时，满足条件的记录会先以 `pending` 入库，再进入抑制评估。

验证：在「标签事件记录」中按规则名 `login-burst` 筛选，能看到新记录。

### 6. 确认告警状态

打开记录详情，确认：

- 状态为 `alerting`（首次触发且不在抑制窗口内）。
- 命中明细中的命中次数大于阈值。
- 原始记录 ID 能在流量审计中对应到具体请求。

验证：在抑制窗口内再次触发同一规则，新记录应为 `suppressed`；等待窗口结束后再次触发，应重新出现 `alerting`。

## 成功标志

「标签事件记录」中存在由 `login-burst` 产生、状态为 `alerting` 的记录，且命中明细可回溯到原始流量。

## 常见问题

- **一直没有事件记录**：确认标签规则已启用且新流量能命中；确认事件规则已启用；确认窗口内命中次数确实大于阈值。
- **状态总是 suppressed**：抑制窗口过长或同一指纹持续命中，按需缩短窗口或调整规则粒度。
- **试运行命中但真实检测不命中**：试运行用的是样例或即时查询，真实检测依赖已聚合的标签数据，确认时间窗口与数据时间范围重叠。
