# 第 4 章：告警事件如何产生

> 状态：草稿（AI 起草）
> 责任人：@olinex
> 依据：`internal/tagengine/event.go`、`internal/models/tag/tag_event_record.go`、`internal/worker/handlers/tag_event`

本章解释从「标签」到「风险告警」的判定链路。读完后再进入第 5 章配置第一条风险规则。

## 你将完成什么

- 说清标签如何按时间窗口聚合成事件。
- 理解条件、阈值、表达式、全部条件满足与抑制窗口的作用。
- 知道事件状态 `pending`、`alerting`、`suppressed`、`closed` 的流转条件。

## 前置条件

- 已有至少一条启用的标签规则，并能稳定产生标签（见[第 3 章](03-first-tag.md)）。
- 能打开「标签事件 → 标签事件记录」。

## 步骤

### 1. 看懂数据流

```text
标签规则打标
  → 按（命名空间, 模型, 标签维度, 维度取值）滚动聚合
  → 标签事件条件按时间窗口统计命中次数
  → 条件阈值判定命中
  → 生成事件记录（pending）
  → 抑制评估
      ├─ 命中抑制窗口 → suppressed
      └─ 未命中 → alerting
  → 投递通知任务
  → 后续同指纹事件到来时，旧记录转为 closed
```

聚合结果存放在标签汇总表中，检测时按条件组装统计查询，窗口内的原始记录 ID 会一并聚合，供事件详情回溯。

验证：在标签事件记录详情中能看到命中条件对应的命中次数、阈值、时间窗口与原始记录 ID。

### 2. 认识条件字段

一条标签事件规则由一条或多条条件组成，每条条件声明：

| 字段 | 作用 |
| --- | --- |
| 条件名称 | 便于在命中明细中辨认 |
| 目标模型 | 只统计该模型，留空表示不限制 |
| 标签维度 / 维度值 | 只统计特定维度或取值，留空表示不限制 |
| 时间窗口（分钟） | 统计窗口，必须大于 0 且不超过 7 天 |
| 阈值 | 命中次数上限，`命中次数 > 阈值` 才算命中，最大 1,000,000 |
| 标签表达式 | 标签的布尔组合，支持 AND / OR / NOT 与括号 |
| 启用 | 关闭后该条件不参与检测 |

表达式示例：

- `http-login`：只要出现该标签即可。
- `http-login AND risk-bad-ip`：两个标签同时出现。
- `http-login OR admin-path`：任一标签出现。
- `NOT http-login`：该标签未出现。

验证：在「标签事件规则」编辑器里点条件上的「校验」，非法表达式会给出对应条件序号的错误。检测阶段无法解析的条件会被跳过；全部条件都无效时返回空结果，而不是报错。

### 3. 理解「全部条件满足」

- `全部条件满足` 关闭（默认）：规则下任一条件命中即触发一次事件。
- `全部条件满足` 开启：规则下所有启用条件都在各自窗口内命中，才触发一次事件。

验证：在同一规则里配置两条条件，切换该开关后分别试运行，观察「检测事件」与「命中 N 个条件」的差异。

### 4. 理解抑制与状态流转

事件入库时状态为 `pending`。抑制处理器按抑制指纹判断是否落在抑制窗口内；指纹由「命名空间 + 规则 ID + 排序后的命中分组（model|dimension|item）」取 SHA-256 得到：

- 落在窗口内：转为 `suppressed`，不发送通知。
- 不在窗口内：转为 `alerting`，并投递通知任务。
- 同一指纹出现更新的事件时，旧记录转为 `closed` 保留历史。

抑制窗口在规则上配置，单位为分钟，默认 60 分钟；设为 0 表示不抑制。

验证：连续两次触发同一规则，第二次应被抑制；把抑制窗口设为 0 后重试，应再次产生 `alerting`。

### 5. 知道事件记录里能看到什么

打开「标签事件 → 标签事件记录」，详情包含：

- 事件基础信息：规则名称、全部条件满足、状态、抑制指纹、检测时间。
- 命中明细：条件名称、模型、维度、维度取值、命中次数、阈值、窗口、原始记录 ID。
- 关联发送记录：通知目标、渠道、发送状态与消息 ID（第 6 章配置渠道后才有内容）。

验证：任意打开一条记录，三个区域都有对应数据或明确的空状态。

## 成功标志

你能准确解释一条告警为什么是 `alerting`、为什么被 `suppressed`，并能从命中明细回溯到原始流量记录。
