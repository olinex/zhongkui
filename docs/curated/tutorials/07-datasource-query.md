# 第 7 章：第三方数据源查询

> 状态：草稿（AI 起草）
> 责任人：@olinex
> 依据：`internal/pkg/sqlitevtab/vtab/datasource_plugin.go`、`internal/tagengine/builtin.go`、`internal/datasource/reload.go`

本章把外部数据（黑名单、资产库、配置中心等）登记为数据源，并在 Rego 规则里用 `sqlite.query` 关联查询。

## 你将完成什么

- 在「数据源」页登记一个第三方数据源并验证连接。
- 在标签规则中用 `sqlite.query` 查询该数据源，命中后打出风险标签。
- 理解命名空间隔离与常见报错。

## 前置条件

- 已完成[第 3 章](03-first-tag.md)，能创建并试运行标签规则。
- 有一个可从平台访问的外部数据源，并知道其连接信息与表结构。
- 当前命名空间有数据源与标签规则的写权限。

## 步骤

### 1. 打开数据源页

进入侧边栏「数据源」（页面标题为「第三方数据源」），点击新建。

验证：新建对话框包含名称、类型、启用、连接配置、描述。

### 2. 选择类型并填写连接配置

当前支持的类型：

| 类型 | 说明 |
| --- | --- |
| `postgres` | PostgreSQL 业务表 |
| `mysql` | MySQL / MariaDB 业务表 |
| `clickhouse` | ClickHouse 业务表 |
| `mongo` | MongoDB 集合，表结构需手动填写 |
| `redis` | Redis 键值、Hash、List、Set、ZSet |
| `etcd` | etcd 键值 |
| `sqlite_file` | 上传 SQLite 数据库文件，文件加密存储于 S3 |

以 PostgreSQL 表为例，常见配置为主机地址、端口、用户名、密码、库名、表名。

验证：配置字段会随类型变化；缺少必填项时保存按钮不可用。

### 3. 测试连接与自省表结构

- 点击「测试连接」，确认网络与凭据可用。
- 点击「自省表结构」，把列名与类型写入列定义。
- MongoDB 不支持自省，必须手动填写完整列定义。

验证：自省后「列」区域显示列名与类型；保存前列定义不能为空。

### 4. 保存数据源

填写名称并保存。

名称会成为 Rego 中的表名，规则里直接使用裸名，不需要命名空间前缀。

验证：数据源列表出现该记录且为启用状态；同名数据源在不同命名空间互不影响。

### 5. 在 Rego 中查询

假设登记的数据源名为 `threat_ip`，包含 `ip` 列。新建或编辑标签规则：

```
package zki

import rego.v1

tags contains "risk-bad-ip" if {
	rows := sqlite.query("select ip from threat_ip where ip = ?", [input.clientIp])
	count(rows) > 0
}
```

要点：

- 第一个参数是 SQL 字符串，第二个参数是绑定参数数组；用 `?` 占位，不要拼接字符串。
- 返回行对象数组，每行以列名为键。
- 查询是只读的：连接级 authorizer 拒绝写操作；单次查询默认最多返回 1000 行，超出会报错，查询应带上足够精确的过滤条件。
- 同一参数在一次评估内会复用结果。
- 数据源按命名空间隔离，规则只会查到当前命名空间登记的数据源。

验证：在规则编辑器点「试运行」，样例中的 `clientIp` 命中黑名单时应出现 `risk-bad-ip`；改成未命中的 IP 后标签消失。

### 6. 观察真实流量

保存并启用规则，等待新流量进入。

验证：流量详情中出现 `risk-bad-ip`；事件规则可以继续引用该标签（见[第 5 章](05-first-risk-rule.md)）。

## 成功标志

规则能在试运行与真实流量中查询到外部数据，并按预期打出风险标签。

## 常见问题

- **`sqlite pool not activated`**：求值上下文没有绑定该命名空间的数据源池，确认规则在标签引擎路径执行、数据源已启用并完成注册。
- **表或列不存在**：以「自省表结构」的结果为准，注意大小写与裸表名。
- **类型错误**：评估启用严格内置函数错误，SQL 参数类型与列类型不匹配会直接失败；用试运行快速定位。
- **查询不到数据**：确认数据源连接的是当前环境、当前命名空间，以及过滤条件确实能匹配。
