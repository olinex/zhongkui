# 第 0 章：教程总览与系列路线

> 状态：草稿（AI 起草）
> 责任人：@olinex
> 依据：`internal/docs/registry.go`、`docs/curated/tutorials/01-ingest-traffic.md`

本系列从真实流量接入开始，依次走过标签、告警、通知、第三方数据、AI 助手与周期性报告，最后补齐多租户与权限。本章只说明系列的整体安排与阅读路线，不包含具体操作步骤。

## 你将完成什么

读完 13 章后，你可以独立完成一条完整的平台使用链路：

- 把真实网络流量接入平台，并在流量审计中核对记录。
- 编写 Rego 规则、创建标签，并用试运行验证。
- 配置标签事件条件，看到风险告警并投递到邮件或 Webhook。
- 在规则中查询第三方数据源，扩展判定依据。
- 启用 AI 助手，用自然语言分析数据，并与其共创 Rego 规则与周期性报告。
- 创建命名空间、用户与用户组，完成多租户隔离和权限分配。

## 系列路线

本系列按依赖顺序推进，建议按章节阅读：

| 章节 | 完成后你能做什么 |
| --- | --- |
| 第 1 章 接入流量 | 让真实流量进入平台，并在流量审计中看到记录 |
| 第 2 章 Rego 规则讲解 | 读懂平台标签规则的契约、输入文档与校验机制 |
| 第 3 章 实现你的第一个标签 | 创建并验证第一条标签规则 |
| 第 4 章 告警事件如何产生 | 理解标签如何聚合成事件、如何抑制并变成告警 |
| 第 5 章 实现你的第一个风险规则 | 配置条件并看到第一条 `alerting` 告警 |
| 第 6 章 接入告警渠道 | 把告警投递到邮件或 Webhook |
| 第 7 章 第三方数据源查询 | 在 Rego 中查询外部数据源完成打标 |
| 第 8 章 如何接入 AI | 启用 AI 助手 |
| 第 9 章 用 AI 助手分析数据 | 用自然语言查询流量、标签与告警 |
| 第 10 章 与 AI 助手共创 Rego 规则 | 通过对话起草并落库一条风险规则 |
| 第 11 章 周期性报告讲解 | 创建并执行一次周期性报告 |
| 第 12 章 与 AI 助手共创周期性报告 | 通过对话共创报告技能与计划 |
| 第 13 章 命名空间、用户、权限与用户组 | 完成多租户隔离与团队授权 |

## 两条推荐路线

- **最短闭环**：第 1 → 3 → 5 → 6 章，先跑通「流量 → 标签 → 告警 → 通知」。
- **AI 增强**：第 1 → 3 → 5 章打底后，从第 8 章进入 AI 助手、规则共创与周期报告。

> 管理员建议先读第 13 章，确认命名空间与账号权限；本系列前 12 章默认你已经拥有可用命名空间和管理员账号。

## 每章的统一结构

每一章都按同一结构书写，便于按步骤执行与验证：

1. **你将完成什么**：本章结束时的可见结果。
2. **前置条件**：开始前必须就绪的环境、账号与数据。
3. **步骤**：可执行的操作，每一步都带「验证」。
4. **成功标志**：如何判断本章目标已经达成。
5. **下一步**：继续阅读的章节或可选进阶配置。

## 阅读前的整体准备

- 已按[Linux 开发环境部署](linux-dev.md)或任一部署教程完成平台部署。
- 拥有管理员账号与至少一个可用命名空间。
- 准备一台 Linux 采集机用于第 1 章；没有采集机时可先用试运行与样例完成第 2、3 章。
- 第 8 章起需要可访问的对话模型与向量化模型服务；第 11、12 章还需要启用且未过期的访问密钥。
